# TRPG シナリオエディタ

ブラウザだけで動く、TRPG シナリオの執筆エディタです。

**目的は「システムごとに違う複雑なデータを、記述して共有できるようにすること」**です。
日本の TRPG はシステムが非常に多く、NPC データもマップもシステムごとに形が違います。
その「形」をテンプレートとして定義し、**ファイル1つで人に渡せる**ようにするのがこのツールの中心です。

> **状態: 開発初期。文章を書く部分と、画像素材の差し込みまでが動きます。**
> テンプレート機構（このツールの中心）は、**画像 1 本ぶんだけ**が通っている段階です
> ——フォーム入力も、独立章や表の出力も、書き出しへの展開もまだありません。

## 今できること

- **Markdown で本文を書く。** `## ` と打てばその場で見出しになります。
  ⭐ **記号は消えません。** 本物のテキストとしてそこに残り、あとから編集できます
  （`##` を `###` にすれば階層が変わり、消せば普通の段落に戻ります）。
  見出しは**文字を大きくせずに色で**示します——メタデータをメタデータとして扱うための選択です
- **左ペインの見出しツリーで章を並べ替える・階層を変える。**
  項目をドラッグすると順番が、`←` `→` ボタンで階層が変わります。
  ツリーは本文から導出しているので、本文を直せばツリーが、ツリーを動かせば本文が、それぞれ追従します
- **md を貼り付けるとブロックに分解される／md へ書き出して読み戻せる**
- **画像を素材として追加して、本文へ差し込む。** 右ペインの「素材を追加（画像）」で選ぶと
  一覧に並び、「本文へ挿入」でカーソル位置に入ります。**文の途中にも、単独の段落にも置けます**。
  同じ画像を 2 箇所に置いてから差し替えると**両方が変わります**（本文は参照しか持たないため）。
  一覧には「未配置 N 件」が出るので、**足したのに本文へ入れ忘れた素材**が分かります
- **書きかけは自動でブラウザ内（IndexedDB）に保存され、リロードしても残ります**
  （⚠ 保存は打鍵が止まってから 0.5 秒後にまとめて行うので、
  打った直後にタブを閉じると最後の数文字が戻ることがあります）

## できるようになる予定のこと

- **構造化データを本文に差し込む。** NPC・エネミー・マップなどをフォームで入力すると、
  本文の中では小さなスタブとして表示され、出力時に表や独立した章になります
- **その「形」をテンプレートとして定義し、配布できる。** テンプレートは JSON ファイル1つです。
  自分のシステム用に書いて、そのまま人に渡せます
- **書き出し**: Markdown（画像があれば zip）、データそのもの（JSON）

## 技術

- Vue 3 + TypeScript + Vite
- [Tiptap](https://tiptap.dev/)（ProseMirror ベース）
- データはブラウザ内（IndexedDB）に保存されます。**サーバーには送信されません**

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm run build      # 本番ビルド
npm run test:unit  # テスト
npm run lint       # Lint
```

Node.js は `^22.18.0 || >=24.12.0` が必要です。

### 設計の骨格と、それを確かめているテスト

このエディタは「**本文はブロックの配列で、テンプレートのデータは本文の外に置き、
本文にはそのデータが生んだ"パート"への参照だけを置く**」という作りをしています。
これが Tiptap 上で本当に成立するかを、実装に入る前に確かめました
（`src/document/__tests__/partRefIntegration.spec.ts`・`npm run test:unit` で走ります）。

⭐ **同じ 5 つの性質を、参照ノードの 2 種類（ブロックとして置く版・段落の中に置く版）へ
そのまま当てています。** テストを書き写すのではなく同じ本体を 2 回回しているので、
片方だけがこっそり緩い断言になることがありません。

| #   | 性質                                                                   |
| --- | ---------------------------------------------------------------------- |
| 1   | データ 1 件から、配列の件数だけパートが生まれる                        |
| 2   | **同じパートを本文の 2 箇所に置いても、データを直せば両方が変わる**    |
| 3   | データから要素を消すと、本文に残った参照を「行方不明」として検出できる |
| 4   | 本文を走査するだけで「まだ置いていないパートの件数」が数えられる       |
| 5   | 参照を別の位置へ動かしても、データとの紐付けが切れない                 |

### `src/document/` — 本文まわり

- `schema.ts` … エディタの拡張一式とスキーマ（アプリとテストで**同じものを使う**）
- `editor.ts` … エディタを作る唯一の入口（貼り付け経路の配線もここ）
- `outline.ts` … 左ペインの見出しツリーを**本文から導出**する。ツリーは保存しない
- `sections.ts` … 並べ替え・階層変更（どちらも本文への操作として書かれている）
- `markdown.ts` … md の読み書き。**md は入出力形式の一つで、真実は本文側**

### `src/template/` — テンプレート層

- `model.ts` … テンプレ定義・インスタンス・パートの型と、**パートの導出**
- `loader.ts` … 定義の読み込み。**同梱品も持ち込みもこの 1 本を通ります**
- `schema.ts` … 定義の検証。壊れた JSON には**どこが悪いかを全部**書いて返します
- `outputs.ts` … 「どんなパートを・どんな形で生むか」の宣言の型
- `render/` … 組み込みパターンの実装（今は画像 1 本）

`src/templates/` は同梱テンプレート定義（**普通の JSON**）の置き場です。

### `src/store/persistence.ts` — 保存

IndexedDB に、本文の JSON と素材（画像を含む）を保存します。見出しツリーもパートも
素材一覧も保存しません（どれも導出できるので、保存すると二重管理になります）。

## テンプレートについて

テンプレートは **JSON で定義された「入力フォームと出力の形」**です。
**同梱品も、あなたが持ち込んだものも、まったく同じ扱いになります**
（同梱テンプレートに特別な仕組みは持たせません。同梱品も、持ち込みとまったく同じ読み込み経路を通ります）。

⚠ 現時点で同梱テンプレートは **「画像」1 つだけ**です（`src/templates/image.json`）。
画像の差し込みに専用の仕組みは無く、**画像もテンプレートのインスタンス 1 件**として扱われます。
⚠ **テンプレートを読み込む UI はまだありません**——持ち込みの経路はコード上に用意されていますが、
画面から選ぶことはまだできません。

### ⚠ 持ち込んだテンプレートについての注意

テンプレートは**出力に自由な HTML を書けるようにする予定**です。表現力のためにあえて制限しません。
そうなると、**あなたが読み込んだテンプレートは、あなたのブラウザの中で HTML として動く**ことになります。

- ⚠ **自由 HTML はまだ実装されていません。** 現時点で出力できるのは、アプリに組み込まれた
  パターン（今は画像だけ）を JSON から選ぶところまでです。下の注意は、**実装した後の話**として
  先に書いてあります。

- ⚠ **この隔離はまだ実装されていません。** アプリ側では、テンプレートの出力を
  **隔離した領域（sandbox 付き iframe）で描画する予定**です。実装されれば、
  テンプレートからあなたの保存済みシナリオを読み出すことはできなくなります。
  **それまでは、この保護は無いものとして扱ってください**
- それでも、**出どころの分からないテンプレートを読み込むのは、出どころの分からない
  ファイルを開くのと同じこと**だと考えてください
- **リポジトリに同梱されているテンプレートは、メンテナが目を通したものです**

## テンプレートを送りたい方へ

Pull Request を歓迎します。ただし **入るかどうかは分かりません。**
入れる以上はこちらの責任になるので、内容を見て判断します。落としても他意はありません。

- ルールブックの**本文をそのまま転記したもの**は入れられません
- 入らなかった場合も、**あなたのテンプレートはあなたが自由に配布できます**
  （ファイル1つで渡せる形にしてあるのは、そのためでもあります）
